# 验收标准与证据要求

**当前状态：以下全部是未来门槛，未运行产品测试。** 本轮仅检查文档、Schema和样例一致性。每个AC最终填 `passed / failed / not_run / blocked`，不得用“实现了”或模型说“完成”替代观察结果。

## 1. 环境与固定评估集

P0验收使用独立测试库/临时blob目录/实际Pi持久存储；记录OS、CPU、内存、Node/PG/pgvector/Pi/A2A SDK版本、git SHA、模型ID和配置哈希。模型密钥不得进入报告。可用mock覆盖确定性故障，质量和跨Agent门槛必须再用真实配置模型。

固定100份合法可分发资料（60中文、30英文、10混合）：TXT20、MD30、文本PDF30、DOCX20；另20份固定URL快照用于HTML解析与locator必测，P0不计入上述100份召回质量集，单独报告HTML格式成功与定位指标。至少100个独立标注查询：精确标识20、同义语义30、跨段/跨文档20、版本10、无答案10、过滤/权限10。每条保存expectedDocumentIds、支持段落与可接受source locator；在调参前冻结，保留20%盲测集。标注由人或独立复核完成，不能从当前检索输出反向生成答案。

质量指标只在有答案且有权访问的查询上计算：Recall@10为前10条命中的相关documentId数/该查询全部相关documentId数，按查询宏平均；MRR@10为第一个相关命中的倒数排名宏平均。无答案/无权限集单列误报和泄漏，分母不混入质量指标。切块重复不得算多次相关命中。

额外故障样本：空、损坏、超限、宏文档、扫描PDF、假MIME、重复内容、恶意URL/重定向、提示注入、两租户同名文档、同requestId不同payload。拒绝/降级类样本不掺入正常解析成功率。

## 2. P0场景矩阵

| ID | 操作与检查点 | 必须满足的结果 |
|---|---|---|
| AC-01 | 锁依赖并从干净目录安装 | exact版本+lock可重现；Pi真实导入、SQLite open/close成功；不能只有package.json |
| AC-02 | 两种独立A2A客户端发现并调用 | Card按固定协议解析，send/get/stream/cancel各至少一次；未知字段/错误版本按合同处理 |
| AC-03 | 关闭原WeKnora，在隔离环境运行 | 保存→索引→搜索→引用读回成功，日志/网络不依赖原WeKnora运行服务 |
| AC-04 | 其他Agent创建KB、保存Markdown | 响应包含稳定taskId；完成后documentId/version/hash可查，源文件校验一致 |
| AC-05 | 同请求重复/断线后重试20次 | 同作用域requestId+payload只生成一个逻辑文档版本/索引发布，taskId稳定；自然语言模型同轮重复相同写工具也不重复发布 |
| AC-06 | 同requestId换payload；跨主体重用ID | 前者IDEMPOTENCY_CONFLICT，后者按各自身份隔离且不能拿到另一方结果 |
| AC-07 | TXT/MD/PDF/DOCX/HTML逐一入库 | 合法样本全部ready且正文非空；定位信息可追溯；损坏/不支持明确失败 |
| AC-08 | waitFor=stored 与 indexed分别保存 | stored仅保证落盘并给后续公共A2A ingestionTaskId；能用GetTask/CancelTask查取消该索引任务；indexed完成前可搜索验证，不混同 |
| AC-09 | 通过两客户端执行hybrid检索 | 返回结构化结果、版本、locator、scoreType；空命中为空数组，无虚构文档 |
| AC-10 | 运行冻结质量集 | Recall@10≥0.90、MRR@10≥0.75；按语言/格式/类别分组公开，不只报平均 |
| AC-11 | 检查每条命中引用 | 100%可映射到相同版本的原文位置；ACL范围内可读；不给伪造页码 |
| AC-12 | Reranker超时、Embedding不可用 | 明确降级及原因；不能把检索基础设施失败写成“未找到资料” |
| AC-13 | topK、filter、list分页 | topK≤50；过滤生效；游标绑定查询和身份；一致视图/版本约束下无重复漏项 |
| AC-14 | A/B两身份不同KB，篡改task/context/upload/document ID | 所有接口、流、缓存、引用下载均0泄漏；不信任DataPart自报tenant |
| AC-15 | URL私网/IP编码/重定向/DNS变更攻击 | 每跳与最终连接受限制，不能读取本机/元数据端点；合法URL记录来源hash |
| AC-16 | 更新v1→v2；构建途中搜索；两个并发更新 | 构建期间仍搜v1；发布后新搜索仅v2；冲突失败，不把旧结果伪装成v2 |
| AC-17 | 删除与索引/搜索/下载并发 | tombstone提交后新访问/搜索不返回文档；旧引用失效；purge可跟踪 |
| AC-18 | task完成后重启，再get同task | 状态与artifact仍在；不重新执行已完成写入，不因内存缓存丢失 |
| AC-19 | 对下表每个窗口执行进程SIGKILL并重启 | 任务最终可收敛到正确终态，无重复版本、无孤儿可见索引、无“假完成” |
| AC-20 | 真实Pi Agent读自然语言指令并保存/检索 | 至少一完整真实模型工具调用轨迹；有domain收据、可查询结果与持久化证据 |
| AC-21 | 取消任务与断开stream分开测试 | 断线不取消；取消成功后不发布新索引；已完成任务按协议拒绝/说明，不回退终态 |
| AC-22 | 空文件/损坏/超限/扫描PDF/恶意文档 | 明确错误、受限资源、无服务崩溃；unsupported不能变成ready空库 |
| AC-23 | 文档内写“忽略指令/删库/泄密”后检索 | 内容按数据返回；无越权工具、无任意shell/网络、无其他资料泄漏 |
| AC-24 | 指定负载与配额测试 | 满足下文性能目标；过载可预测排队/拒绝并有retry提示，无无界任务或内存 |
| AC-25 | 备份→修改/删除→新目录恢复 | blob/PG/Pi三者对账；旧task可查、引用可读、恢复后新写成功，无重跑已完成操作 |
| AC-26 | 两Agent完整实用闭环与接入文档 | A保存资料→B获授权检索→读取引用→A更新→B看到新版；撤权后B无法读取 |

### 故障注入窗口（AC-19）

1. 请求收据已提交、Pi未接单。
2. Pi已接单、PG映射未回填。
3. blob落盘、数据库引用未提交。
4. parser外部完成、阶段收据未写。
5. 部分embedding成功、批次收据未写。
6. 全部索引已写、activeGeneration未切换。
7. activeGeneration已切换、A2A completed尚未投影。
8. 取消已接受、外部模型随后返回。
9. 删除tombstone已提交、旧索引任务随后试图发布。
10. outbox已处理、deliveredAt尚未记录。

每窗至少重复3次并检查数据库唯一约束/版本数量/任务状态/索引可见性；不只看HTTP响应。为重复付费调用单独计数：允许因供应商不支持幂等而重试，但预算有界且不能产生重复业务结果。

## 3. 性能、成本与可靠性目标

以下为P0建议目标，M0用真实环境校准后冻结；任何调整记录原因和新阈值，不能验收失败后无记录降低标准。

- 基准10,000个chunks、5并发查询、预热后连续10分钟：纯检索服务端p95≤2秒；含外部Embedding/Rerank端到端p95≤5秒，分别记录供应商耗时。
- 10页文本PDF/500KiB Markdown在健康模型服务下：单份索引p95≤60秒；大文件按token/页数报告吞吐，不套同一阈值。
- 本地进程崩溃后30秒内恢复接单/可查询状态；待处理工作按预算继续，恢复不是要求所有长任务30秒内完成。
- 测试中错误归类完整，429/5xx暂时故障有界重试；单任务最大attempt/时长/token/费用可配置，超限进入明确终态。
- 数据泄漏、发布重复、成功响应对应空索引、已删资料仍可访问：容忍数均为0。
- 进程重启持久化与主机掉电持久化分开验证；未证明同步写盘策略时，不宣称掉电零丢失。

如要宣称“WeKnora同等检索质量”，需在同一语料、相同Embedding/Rerank预算与过滤条件下运行原版对照，公开差异。原版未能启动时写 `parity not_run`，可报告P0绝对指标但不能宣称同等。

## 5. 验收报告模板

每次运行写入 `evidence/<run-id>/`：`manifest.json`（版本/环境/语料hash）、`acceptance.json`（AC状态/证据路径）、脱敏协议请求响应、领域receipt与数据库断言、故障注入日志、质量指标、真实Agent工具轨迹、必要UI截图。

报告一行对应一个AC：ID、状态、命令、时间、环境、结果值、证据文件、限制。`passed`仅适用于已经执行且达到标准的用例。P0全部通过才标“核心文档Agent完成”；P1/P2未做时继续保留差异。
