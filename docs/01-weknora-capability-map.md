## Pi Durable 与 A2A 的实现边界

当前基线有对外 MCP Server：按 endpoint token、工具 allowlist、KB scope 和 rate limit 暴露 `list_knowledge_bases`、搜索、读文档、添加/更新/删除文档等工具。[MCP route](https://github.com/Tencent/WeKnora/blob/2fbfb4471581cd5e7d731bc7a2d443fe7d8e95b5/internal/router/routes_mcp_endpoint.go#L31-L48) [MCP server boundary](https://github.com/Tencent/WeKnora/blob/2fbfb4471581cd5e7d731bc7a2d443fe7d8e95b5/internal/mcpserver/server.go#L1-L12) [MCP tool auth/filter/rate-limit](https://github.com/Tencent/WeKnora/blob/2fbfb4471581cd5e7d731bc7a2d443fe7d8e95b5/internal/mcpserver/server.go#L146-L182) [MCP ingest contract](https://github.com/Tencent/WeKnora/blob/2fbfb4471581cd5e7d731bc7a2d443fe7d8e95b5/internal/mcpserver/tools_ingest.go#L12-L45) 本次对核心 Go/配置源码检索没有找到 A2A Agent Card 或 A2A 协议处理路径；这只是代码检索结论，不是运行时探测。

建议将 Pi Durable 作为持久 Agent 运行时，将新服务作为知识库与索引服务，将 A2A adapter 做成 Pi Agent 的外部入口。A2A wire/data part 与 Pi 内部工具名分层；公共业务操作统一为 `knowledge_base.create/list`、`document.save/search/get/list/update/delete`，adapter 映射到 03 中的 Pi tool registry，不让 MCP JSON-RPC 冒充 A2A。保存内容和解析/索引用有状态 task，返回稳定 A2A task/document ID。二进制上传走 A2A 文件 part 或独立、带 principal scope 的 HTTPS uploadId，不传宿主机路径。Agent Card、消息接收、任务查询/取消按最终选定的 A2A 规范版本实现。

几个必须分清的持久状态：

- **Pi Durable** 保存 Agent 会话、轮次/运行与 A2A task 对应关系；服务重启后能按同一 task ID 继续查状态。
- **知识服务**保存 KB、文档源文件、revision、chunk、索引与权限归属；Agent 会话持久化不能代替这些业务数据。
- **文档处理调度**由 Pi 原生 custom Tasks 承担；PG `outbox` 与 `processing_receipts` 保存跨存储投递意图、阶段输入/输出和恢复依据，不负责再次调度模型任务。不引入 Redis/Asynq 作为第二个 scheduler。[Pi/PG职责边界](./03-product-architecture.md#3-组件与唯一职责) [流水线收据与outbox](./05-data-and-pipelines.md#1-数据表与约束)
- WeKnora 的实现用 Asynq/Redis；无 Redis 的 Lite 路径则是 goroutine 内存执行，进程退出会丢失未完成任务。这是被分析项目的事实，不是新服务的选型。[Lite executor](https://github.com/Tencent/WeKnora/blob/2fbfb4471581cd5e7d731bc7a2d443fe7d8e95b5/internal/router/sync_task.go#L22-L34) [Lite goroutine dispatch](https://github.com/Tencent/WeKnora/blob/2fbfb4471581cd5e7d731bc7a2d443fe7d8e95b5/internal/router/sync_task.go#L134-L180) [Redis worker setup](https://github.com/Tencent/WeKnora/blob/2fbfb4471581cd5e7d731bc7a2d443fe7d8e95b5/internal/router/task.go#L133-L145)

按层复用建议：

1. **可移植算法**：chunker、RRF、locator schema 是价值最高的实现参考；可抽成公开模块或在新仓库按 MIT 条款复制后适配。当前代码位于 Go `internal/` 包，独立 module 不能直接 import WeKnora 的 `internal/...`，不能把“可以复用”写成已存在稳定 SDK。
2. **解析器**：优先把 DocReader 当独立 gRPC 服务复用。它仍依赖具体 Python 环境、外部 OCR/VLM、对象存储可达性与配置；必须在新服务验明文件字节/URL、图片产物与 locator 协议，不可假设解析器可无条件调用。
3. **需要重写/适配**：WeKnora 的 service/repository/container 与租户上下文、GORM 模型、存储/向量仓库、model catalog、异步 task、前端/Agent 对话相互耦合。复制整个业务 service 不是“接入 Pi”；应在新应用边界实现文档 use case、存储/embedding/vector/parser ports，再将它们挂到 A2A 与 Pi Durable。
4. **来源引用**：可参考 WeKnora `SourceLocator` 与 search result 结构；A2A 回传结构化 `evidence[]`（doc/chunk/revision/quote/locator），由消费 Agent 负责答案表达。WeKnora 的 `<ref id="cN"/>` 是每次模型调用私有 handle 协议，不能直接当成跨会话稳定 ID。[citation protocol](https://github.com/Tencent/WeKnora/blob/2fbfb4471581cd5e7d731bc7a2d443fe7d8e95b5/internal/modelcontext/citations.go#L14-L40)

## P0 验收标准与容易漏掉的风险

| 验收项 | 可观察结果 |
|---|---|
| 真正的 A2A 接入 | 使用独立 A2A client 读取 Agent Card，调用检索与保存能力；检索能返回结构化结果，新增文档先返回持久 task ID，后续查询最终到 `completed`/`failed`。不以 HTTP 200 或 MCP 测试代替 A2A 证明。 |
| 文档闭环与定位 | TXT/MD、文本 PDF、DOCX、公开 HTML 五种 P0 输入各有固定样本；解析、检索均返回 document/version/chunk 与 locator；引用能指回同一版本原文。缺定位、错位置或不能读回的格式测试失败，并移出 P0 直至修复，不能以 `locator_missing` 通过。 |
| URL 安全和类型分流 | 公开 HTML 页面可入库；localhost、私网/云 metadata、非法 scheme、恶意重定向目标被拒；下载大小、超时与解压比有限。 |
| Durable 与幂等 | Pi custom Task 入队后重启拥有 Pi SQLite 的进程，A2A task/doc IDs 不变且任务能恢复；PG outbox/phase receipts 对账能修复 Pi 与业务投影窗口；重复重试不产生重复版本/chunk/vector；并发替换时旧 generation 不覆盖新版本；取消与删除竞态不能复活旧索引。 |
| 发布/更新/删除 | P0 `document.save` 默认直接发布并等待 indexed 后完成，不涉及草稿；更新需要 expectedVersion，旧 generation 在新索引 ready 前继续服务，发布后旧正文不可见；删除后立刻逻辑不可访问，物理清理由 purge state 追踪。 |
| 标签与权限隔离 | 文档保存/更新标签并按标签过滤搜索；两个 KB 与两个 principal 做正反用例：未经授权不能 list/search/get/save/update/delete；`knowledge_base.create/list` 与 document 操作按主体 scope 限权；错误不能泄露其他 KB 是否存在。 |
| 检索失败可判别 | embedding/vector store/rerank 故障不能被伪装成“没有相关文档”；返回阶段、错误、fallback/实际模式与 task 状态，重试有上限和最终失败状态。 |

重点风险：WeKnora 上传可以“已保存但排队失败”后返回记录；P0 locator 是硬门槛，缺少来源映射的样例或格式不能留在 P0；Rerank 不可用时会退回初始候选顺序；WeKnora Lite queue 不具备进程外持久性，但新服务调度归 Pi custom Tasks、PG outbox/receipts 只做投递和恢复；WeKnora 完整组织分享/四角色 UX 不等于目标服务的主体+KB ACL。P0 直接保存不包含草稿管理。
